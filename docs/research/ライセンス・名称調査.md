# ライセンス・名称調査（mortal-jan）

2026-09-30時点。法的助言ではなく、一次情報に基づく調査。
確からしさ: 確実＝条文・当事者の表明で直接確認できる／有力＝条文とFSFの解釈から強く推定できる／不明＝確認できない。

## 結論の要約

1. MortalのAGPLによる義務が生じるのは、Mortal（パッチを含む）を**配布する**場合と、**改変版をネットワーク越しに使わせる**場合だけ。問題生成を私的に実行するだけなら義務はない。公開する場合はAGPL互換で出す必要があるが、現方針（AGPL-3.0-or-later）で満たしている。【有力】
2. 問題データ（局面と評価値）と、Mortalを実行しないWeb部分には、MortalのAGPL（第13条を含む）は及ばない。重みの利用にもライセンス上の追加条件はない。【有力】
3. 現方針で欠けている義務は1点。libriichiパッチに「改変した旨と日付」「AGPLで提供する旨」の表示がない（第5条a・b）。【有力】
4. 「Mortal」の商標登録は米国では見当たらない（日本は未確認）。AGPLに第7条の追加条項もない。主なリスクは法的なものより、画面の「Mortalの判定」やOGPの表記が**公式Mortalの評価だと誤認させる**点にある。作者は、自分で学習した重みを一度も公開していないと明言している。【商標: 米国は有力、日本は不明／作者の表明: 確実】
5. 最小限の対応: パッチに改変表示を入れる。評価の表記を重み名に変える。サイト名・共有画像に「非公式」と明示するか、サイト名から「Mortal」を外す。

## 根拠

### 1. AGPLの伝播範囲

**(a) 問題生成プログラム**
- 私的利用: 第2条は、配布（convey）しない covered work を無条件で作成・実行できると定めている。第0条は、ネットワーク越しの対話だけでは配布に当たらないと定義している。FSFのFAQも、改変版を私的に使うだけなら公開は不要としている。【確実】
- 第13条: 対象は、利用者がネットワーク越しに対話する改変版。FSFのFAQは、ネットワーク越しに要求を受けて応答するよう設計されたプログラムを対象としている。パッチ済みlibriichiを含む生成プログラムはローカルで実行するだけなので、第13条は発生しない。【有力】
- 公開する場合: パッチは「Mortalに対する改変」をソースの形で配布するものなので、第5条が適用される。Mortalのモジュールを import するPythonスクリプトは、FSFの解釈では同じアドレス空間で関数を呼び合う1つの結合プログラムに当たる。この解釈に立つと、配布するならAGPL互換のライセンスが必要で、AGPL-3.0-or-laterはこれを満たす。なお、importが法的に派生物を作るかは裁判所が判断する事項だと、FSF自身も述べている。【有力】

**(b) 問題データ**
- 第2条により、実行結果の出力が対象になるのは、出力の内容そのものが covered work に当たる場合だけ。FAQも、出力は原則としてプログラムの著作権の対象外であり、例外はプログラム内の文章や画像がそのまま出力に含まれる場合だとしている。問題データは局面と数値で、Mortalのコードや素材を複製していない。【有力】
- さらに日本法では、表現に至らない指示でAIが生成したものには著作物性が認められない、という文化庁の整理がある（p.40）。機械が生成した局面や評価値は、そもそも著作物に当たらない可能性が高い。【有力】

**(c) Webサービス部分**
- 第13条の義務を負うのは、Mortalを改変し、その改変版をネットワーク越しに提供する者。WorkerとフロントエンドはMortalのコードを含まず、実行もしないため、Mortalの改変版に当たらない。生成とWebはデータ（SQLの投入）でしか繋がっておらず、FAQの基準でも別々のプログラムになる。【有力】
- Webのソースを公開・表示しているのは、自作コードの著作権者としての任意の選択である（ライセンサーは自分のライセンスに縛られない）。外部からの貢献を受け入れた場合も、現在のフッターのソースリンクで第13条相当を満たせる。【有力】

**(d) 重み mortal-298k**
- 固定しているリビジョン（dbbea7e）のLICENSEは、AGPLv3の本文そのままで、追加条項はない。モデルカードの注意書きは「ランク戦での使用は非推奨」と「データセットを使うときは天鳳の規約を守ること」だけで、ライセンス上の条件ではない。【確実】
- 改変しない実行は、第2条で無制限に許諾されている。出力の扱いは(b)と同じ。重みはリポジトリに含めず、setup.ps1が取得するため、再配布に伴う義務も生じない。【有力】

**(e) 現方針で不足しているもの**
- 不足: `tools/mortal/libriichi-selfplay.patch` は `diff --git` から始まっており、改変した人・日付・ライセンスの表示がない。第5条a（改変した旨と日付を目立つように表示する）と第5条b（本ライセンスで提供する旨を表示する）に照らすと不足している。gitの履歴だけで足りるかは、解釈が分かれる。【有力】
- 任意: README・ソースに著作権表示（Copyright行）がない。これはAGPL末尾「How to Apply」の推奨で、自作部分については義務ではない。【確実】
- 不要: 第5条d（画面に法的通知を表示する）は、Mortalの改変版が対話的なUIを持つ場合の義務。Mortal自体が表示しておらず、WebもMortalの改変版ではないため不要。【有力】
- 充足: THIRD_PARTY_NOTICES の記載（Mortal、重み、牌画像）は十分。Mortalのロゴ（CC BY-SA 4.0）は使っていない。使う場合は、クレジットの表示と同じライセンスの継承が必要。【確実】

### 2. 「Mortal」の名称

- **米国の商標**: USPTOの商標検索で、文字商標に「MORTAL」を含むもの127件（うち存続60件）を確認した。「MORTAL」単独で存続しているのは、飲料（32類）、衣類（25類）、テレビ・携帯電話などのハードウェア（9類）だけ。ソフトウェア・オンラインゲーム・麻雀・AIの分野に単独の「MORTAL」はなく、Equim名義の出願はゼロ。9類・41類には「MORTAL KOMBAT」などの結合商標があるが、「Mortal何切る」との類似性は低い。【有力】
- **日本の商標**: J-PlatPatをこの環境から検索できず、未確認。【不明】
- **作者の表明**:
  - 名称やロゴの使用ポリシーは、README・ドキュメント・Issue・Discussionsのいずれにも見当たらない。ロゴなどの素材はCC BY-SA 4.0。【確実】
  - AGPLを選んだ理由の一つに、改名されて事情を知らない人に売られることへの懸念を挙げている（ドキュメント「Meta」）。【確実】
  - 学習済みモデルは公開予定なし（Gist、2022-08-19）。自分で学習した重みは一度も公開していない（Discussion #97、2025-04-15）。したがって流通している重みはすべて第三者製。【確実】
  - 第三者の重みそのものへの言及はない。第三者の派生プロジェクト「Mortal-Policy」は好意的に評価しており（Discussion #91）、麻雀一番街には別のライセンスを提供している（Discussion #79）。【事実は確実／好意的な態度が他の事例にも当てはまるかは不明】
- **AGPL第7条**: MortalのLICENSEはAGPLv3の本文と同一（改行位置だけが異なる）。第7条e（商標権は許諾しない、とする条項）などの追加条項はない。ただしAGPLは著作権の許諾なので、名称を使えるかどうかは商標法・不正競争防止法で別に判断される。【確実】
- **リスク**:
  - 登録商標がなければ、商標権侵害のリスクは低い。登録があったとしても、「powered by Mortal」のような説明的な表示は、出所を示す使い方でなければ商標権が及ばない（商標法26条1項6号）。一方、サイト名の先頭に置く使い方は、出所の表示と見られやすい。【有力】
  - 実際のリスクは誤認にある。画面の「Mortalの判定」「候補ごとのMortal評価」や、OGPの「麻雀AI Mortalの評価で採点」は、フッターの「公式モデルではありません」と矛盾しており、公式Mortalの評価と受け取られうる。共有画像やハッシュタグは、フッターなしで広まる。改名転売に対する作者の懸念とも衝突しうる。【有力】

## 不明点

- 日本での「Mortal／モータル」の商標登録（9類・41類・42類）。
- 重みに著作権が生じるか、したがって重みのAGPLが有効か（各国で未確定）。ただし本件の使い方では結論に影響しない。
- 重みの学習データ: モデルカードによると、天鳳の牌譜で学習している。天鳳のマニュアルは、牌譜を天鳳の対戦を必要としないサービスへ応用することを認めておらず、一般の麻雀への応用には問い合わせを求めている。重みの下流利用者にこれが及ぶかは不明（天鳳と契約関係はなく、牌譜に著作物性があるかも疑わしい）。ただし、重みの配布元が抱える問題を引き継ぐという評判上のリスクはある。
- 「Mortal」を冠した第三者サービスを作者がどう受け止めるか（明示の方針はない）。

## 推奨（最小限の対応）

1. パッチの先頭（`diff --git` より前。git apply は前置きの文章を読み飛ばす）と `self_play.rs` の先頭に、改変元（Mortal、固定commit）・改変者・日付・AGPL-3.0-or-later を書く（第5条a・b）。
2. 評価の表記を実態に合わせる。「Mortalの判定」「Mortal評価」は「AI評価（mortal-298k）」などに、OGPの「麻雀AI Mortalの評価で採点」は「Mortal用の第三者重みで採点」などに変える。
3. サイト名は人間が判断する。維持するなら、サイト名・OGP・共有画像に「非公式」「Mortal作者とは無関係」を入れる。より安全なのは、サイト名の先頭から「Mortal」を外し、「〜（powered by Mortal）」の形にすること。どちらにする場合も、事前にJ-PlatPatで「モータル／MORTAL」（9類・41類・42類）を確認する。最も確実なのは作者に一言確認すること（連絡先はGitHubプロフィールのメール。Issue #54で作者自身がそう案内している）。
4. 任意: READMEにCopyright行を追加する。
