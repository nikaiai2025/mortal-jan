# mortal-298k の精度と公式Mortalとの一致度（調査日 2026-09-30）

## 結論
1. **298kの強さを、公式Mortal・人間・天鳳段位と比べた公表値はない。** 独立した測定は、第三者の重み mortal-582500 との1対3対局（各8,000半荘）だけ。298kのほうがやや劣るが、差（1.49pt/半荘）は統計的に有意でない。【確実】
2. **公式4.xとの一致度は、298kの作者の自己申告「mjai.ekyu.moe でAI一致率83〜92%」しかない。** 比較した公式の版、半荘数、数えた判断の種類は書かれていない。第三者による検証は見つからなかった。近いものは、公式「1.0」より前のモデルとの1半荘（105判断）で1位一致89.5%という報告が1件あるだけ。【確実】
3. **298kは公式と作り方が違う。** 重みファイル内の記録では、オフライン学習（CQL）だけで作った途中の重みで、予定した学習の10.8%の時点にあたり、学習率はほぼ最大のまま。ネットワークは40ブロック×192チャネルで、公式3.x/4.xは24ブロック×512チャネル。Q値の尺度も公式と大きく違い、2位以下の候補の順位は、1位よりも公式と食い違いやすい可能性がある。【記録は確実／公式4.xの構成は有力／順位の食い違いは推測】
4. **公式の版の間の差は小さい。** 1対3・各100万半荘で、4.1a/b/c を1人入れると 4.0 の3人に対して+0.25〜+0.42pt/半荘、4.0と3.1の差は約1〜2pt、akochanはMortal 3.1の3人に対して約-5.7pt。人間との比較や段位換算は、作者自身が「分からない」としている。【確実】
5. **一致度は、手作業でなら自前で検証できる。** 自己対局をtenhou.net/6形式に変換して mjai.ekyu.moe の任意牌譜入力で1座席ずつレビューさせ、保存したページを298kの評価と突き合わせる。送信のたびにCloudflare Turnstileの通過が必要で、自動化は想定されていない（利用規約のページはない）。結果は15日で消え、URLを知っていれば誰でも見られる。50座席（約7,000判断・約120問）で手作業1〜2時間。【仕様は確実／工数は推測】

## 1. mortal-298k の精度・強さ

### 事実
**モデルカード（リビジョン dbbea7e）**【確実】
- 学習データ: 天鳳の高段位の四麻半荘（2025〜2026年）。
- 性能の主張: mjai.ekyu.moe のAI一致率83〜92%と、雀魂のMAKA（雀魂公式のAI牌譜解析）で平均S+。どちらも条件は書かれていない。3/18の版では「89〜92%」で、3/21に現在の値へ直している。
- 作者の他の公開物: Hugging Face には、ほかに音声合成の重みが1つあるだけ。カードが参照するデータセット（VoidShine/mortal-dataset）は非公開か、存在しない。Discussions は0件。

**重みファイル内の記録**（手元の mortal_298k.pth から読み取った）【確実】

| 項目 | 値 |
|---|---|
| 観測形式 | version 4（入力1012チャネルで、公式v4と同じ） |
| ネットワーク | ResNet 40ブロック×192チャネル（チャネルアテンション付き）、約1,090万パラメータ |

- 学習に使ったMortalのコミットは記録されていない。上流の最新コミットは本プロジェクトと同じ 0cff2b5（2025-09-28）で、それ以降に更新はない。2026年3月の学習なら、このコミットと同じ観測形式で学習したと考えてよい。【有力】

**独立した評価**【確実】
- ses64276/mortal-582500-vs-298k-benchmark（2026-09-26）: Mortal 0cff2b5 で、1対3を両方向に行った。同じseed（10000〜11999）で座席を回し、各8,000半荘。

| 挑戦者（1人） | 平均順位 | 1位率 | 4位率 | pt/半荘 |
|---|---:|---:|---:|---:|
| 298k | 2.512 | 25.2% | 25.5% | -0.96 |
| 582500 | 2.498 | 25.0% | 24.5% | +0.52 |

  差は1.49pt（95%区間は-0.96〜+3.84で、0をまたぐ）。582500のほうが強い事後確率は約88%。
- mortal-582500 のモデルカードにも、以前の継続学習版（2万ステップ）と298kを比べた結果がある。各256半荘で平均順位は2.410対2.520。標本が小さいことは、カード自身が注記している。
- 公式Mortal・akochan・人間との対局や、天鳳段位への換算は見つからなかった。

### 推測
- 学習率が下がりきる前の途中の重みなので、同じ設定で学習を続ければ強くなる余地がある。582500のカードは、298kを比較の基準にした継続学習と読める。その一例かもしれない。
- 作者Equimは次のように述べている（発言は確実）。オフライン（CQL）だけのモデルは評価が1つの候補に極端に偏る。公式サイトのモデルはオフライン学習のあとにオンライン学習をしているので、分布がなだらかになる。298kも同じ形をしている。手元の自己対局（打牌43,473判断）では、候補間のQ値の幅が中央値で8.4あった。公式レビューの見本ページ（3.x）では、1局面で約1.0だった。1位の選択が妥当でも、2位以下の順位や差は公式と一致しにくい可能性がある。サイトの部分点（100×p/p_max）に効くのはこの部分。

## 3. 公式Mortalの版の間の強さ（物差し）

### 事実【確実】
出典は公式ドキュメントの1対3対局（同じseedで座席を回す。ptの配分は[90,45,0,-135]）。表の値は挑戦者1人の平均pt/半荘で、相手と同じ強さなら0になる。

| 挑戦者（1人） | 相手（3人） | 半荘数 | 挑戦者のpt |
|---|---|---:|---:|
| 4.1a | 4.0 | 100万 | +0.42 |
| 4.1b | 4.0 | 100万 | +0.38 |
| 4.1c | 4.0 | 100万 | +0.25 |
| 4.1b | 4.1c | 100万 | +0.18 |
| 4.1b ／ 4.1a | 4.1a ／ 4.1b | 各100万 | +0.02 ／ +0.03（差なし） |
| 4.0 ／ 3.1 | 3.1 ／ 4.0 | 各100万 | +1.23 ／ -0.98 |
| akochan | 3.1 | 13,152 | -5.67 |

- mjai.ekyu.moe での位置づけ: 4.1cはトップ取り、4.1bはバランス、4.1aはラス回避、4.0はレガシー、3.0は人間に近いが最も弱い。4.1系は2024-08-31に公開。
- Equimによると、強さの主張はすべて1対3の統計に基づく。人間相手の強さは分からない（天鳳にAIアカウントを申請して断られた）。
- 公式3.xのネットワークは24ブロック×512チャネル（見本ページのモデル名 mortal3-b24c512）。4.xも同じ構成（Mortal-Policy作者の発言と、検索結果に出たモデル名 mortal4-b24c512-…）。【3.xは確実／4.xは有力】

### 物差しとしての使い方（推測）
- 両方向の挑戦者ptの差を比べると、298kと582500の差は1.49（有意でない）で、公式の3.1と4.0の差は2.21。ただし298kと公式をつなぐ対局がないので、298kが公式のどの版に相当するかは言えない。
- 第三者の自己申告もある（Mortal-Policyの作者、データは非公開）。オフライン学習にオンライン学習を足した上積みは+0.6pt程度だった。選別した牌譜で作ったオフラインのみのモデルは、既存の公開重みに約+2pt勝った。【不明】

## 4. 一致度を自前で検証する方法

### mjai.ekyu.moe の条件
- 入力: 任意牌譜（tenhou.net/6形式のJSON）を受け付ける。対象は四麻の段位戦ルールで、Mortalは半荘だけに対応する。任意牌譜では対象の座席（0〜3）を指定し、1回の送信で1座席を評価する。【確実】
- 選べるモデル: 4.1c／4.1b／4.1a／4.0／3.0。温度は表示にだけ効き、候補の順位には効かない。【確実】
- 出力: 対象座席の各判断について、実際の選択、Mortalの選択、全候補のQ値とπを示す。全体の一致数/判断数（matches/total）も出る。ページは保存できる。自己対局は4人とも298kの貪欲選択なので、matches/total がそのまま298kと公式の1位一致率の目安になる。【確実】
- 保存期間: 15日。過ぎると削除される。【確実】
- 公開範囲: ログインは不要。URL（/report/＋16桁の16進）を知っていれば誰でも見られ、送った牌譜もページに載る。robots.txt は、一般の検索ロボットには /report/ を禁止し、Internet Archive にだけ許可している。【確実】
- 回数制限: 公表されていない。【不明】
- 自動化: 利用規約のページはなく、FAQにも定めはない。一方で、送信ボタンは Cloudflare Turnstile を通るまで押せないため、自動で送るにはTurnstileを回避するしかない。インフラはスポンサーの提供。したがって自動化はしない。まとまった数を送る前には、作者にGitHub Discussionsで相談する（FAQは質問先にGitHubを指定している）。【仕様は確実／自動化しないという判断は有力】

### 手順
1. 本番ではない自己対局を使う。牌譜の行動は298kの答えそのものなので、本番の牌譜を送ると問題の答えが外部のページに載ってしまう。今の generated/（公開seedの100半荘）なら問題ない。
2. mjai形式からtenhou.net/6形式への変換を作る。プロジェクトにも、見つかった既存ツールにもない。変換結果を mjai-reviewer の convlog（tenhou.net/6→mjai、オープンソース）で戻し、元の牌譜と一致することを手元で確かめる。
3. 問題の多い（半荘, 座席）を50件選び、4.1bで送ってページを保存する。物差しにするため、一部は4.1aと4.1cでも送る。
4. 保存したページから公式の選択とQ値を読み取り、generated/decisions にある298kのQ値と局面ごとに照合する。298kの選択はQ値の最大で取る（規則による和了の制御で、実際の行動と違う場合があるため）。

### 出せる指標
- 全判断での1位一致率（モデルカードの83〜92%と比べる）
- 問題局面での1位一致率。サイトの採点に効くのはこちら。易しい判断を含む全体の一致率より低くなりうる
- 298kの正解が公式では何位か、候補の順位がどれだけ一致するか。Q値の尺度が違うので、pの値ではなく順位で比べる
- 公式の版どうし（4.1a/b/c）の一致率。298kとの一致率を解釈するときの物差しになる

### 規模と工数（推測）
- 手元の自己対局では、1座席・1半荘あたり判断が約143、問題が約2.4問ある。50座席で約7,000判断・約120問。
- 1件あたり1〜2分の手作業で、50件なら1〜2時間、3つの版で送るなら3〜5時間。変換の実装に半日〜1日かかる。
- 95%区間の幅は、問題120問の一致率で±8ポイント程度、7,000判断の一致率で±1〜2ポイント程度。

### 採らない方法
- 公式の重みとの直接対局: 重みが非公開なのでできない。【確実】
- mjai.ekyu.moe の天鳳個室呼び出しで、公式のbotと298kを対局させる: 298kを天鳳につなぐクライアントが要り、対局は実時間で進む。1pt/半荘程度の差を見分けるには数千半荘が要る（8,000半荘でも1.5ptの差は見分けられなかった）。【推測】
