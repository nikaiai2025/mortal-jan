# プロダクト仕様

麻雀の何切る問題を画像で出題し、回答をMortalの評価で採点するWebサービス。問題はMortal同士の自己対局から事前に生成する。ユーザー登録は不要。

評価モデルは第三者が配布するMortal用の重み（mortal-298k）であり、公式モデルではない。サイトにはモデル名・出典・ライセンスとソースコードへのリンクを表示する。

## 画面

| 画面 | URL | 内容 |
|---|---|---|
| 出題 | `/` | 問題画像と回答ウィンドウ |
| 問題の結果 | `/q/{問題番号}` | 自分の回答と得点、候補ごとのMortal評価、人にとっての難しさ |
| 問題集 | `/sets`、`/sets/{問題集番号}` | 一覧（完了状況と得点）、10問の出題、まとめの結果 |
| 成績 | `/u/{公開ID}` | 回答数・平均点・ピタリ率と回答履歴 |
| ランキング | `/ranking` | 期間×評価軸の順位 |

## 出題と回答

- 回答ウィンドウで牌または選択肢をタップして選び、「確定」で送信する。打牌問題は手牌の牌（リーチできる局面ではリーチの有無も）、鳴き問題はチーの組合せ・ポン・スルーから選ぶ。
- `/`ではサーバーが未回答の問題から無作為に割り当てる。
- 回答画面に出した問題は回答するまで割り当て中とし、その間は他の問題を回答画面に出さない（再読込・モード切替・URL指定で問題を選り好みさせない）。
- `/q/{問題番号}`を未回答で開いた場合はその問題を出題する。
- 1問につき最初の回答だけを記録する。問題集でも同じ記録を使う。

## 採点

Mortalは候補ごとに行動の価値（Q値`q`、単位はモデル固有）を出す。これを全問題共通の温度`T = 1.0`で変換する。`T`は公開後に変更しない。

- Mortal評価: `p = softmax(q / T)`。候補の合計が100%になる。
- 得点: `100 × p / p_max`（= `100·exp((q − q_max) / T)`）を整数に丸める。最善手以外は最大99点とする。
- ピタリ: 選んだ手がMortalの最善手と一致すること。
- 候補は行動単位とする。同じ牌種の打牌は1候補、赤5と通常の5は別候補。
- リーチできる局面の候補は、ダマの各打牌と「リーチ＋各打牌」。後者のQ値は、リーチのQ値＋（宣言後の局面での打牌のQ値−その最大値）とする。

## 難易度

- 生成時の分類は`p_max`（最善手のMortal評価）で行う。打牌問題（リーチを含む）は、かんたん: 0.9以上、ふつう: 0.5以上0.9未満、むずかしい: 0.5未満。鳴き問題の閾値は生成データの分布を見て別に定める。
- 人にとっての難しさは、公開後のプレイヤー統計（その問題の平均点）で示す。回答後の結果画面にだけ参考として出し、回答が10件未満の間は出さない。

## 問題集

- 問題番号を10問ずつ区切った1,000個とする（問題集nは問題10n−9～10n）。
- 未回答の問題を番号順に出題し、1問ごとに結果を見せる。10問そろったら得点（合計÷10、0～100点、小数1桁）・ピタリ数・各問の得点をまとめて表示する。
- 他の画面で回答済みの問題は、その回答を問題集の得点に使う。

## 回答後の演出

1問を解いた直後の演出を最重要のUXとして扱う。赤ペンで採点されるような体験にする。

- 得点に応じた印を書き順どおりに描き、ペンで書く音を鳴らす。ピタリは花丸、70～99点は○、30～69点は△、0～29点は✕。
- 印に続いて、得点と候補ごとのMortal評価を示す。
- 演出はタップで早送りできる。音はオン・オフを切り替えられる。

## ランキング

- 期間は全期間と今日（日本時間0時区切り）。
- 評価軸は回答数・平均点・ピタリ率。
- 平均点とピタリ率は、全期間50問・今日10問以上回答したプレイヤーだけを載せる。

## プレイヤー

- 初回アクセス時に匿名プレイヤーを発行し、端末に保存する。端末のデータを失った場合、成績は引き継げない。
- ユーザー名は任意（12文字以内、禁止語を拒否）。ランキングと成績画面に表示し、未設定なら「名無し#公開ID」とする。

## SNS共有

| 共有元 | 画像 | リンク先 |
|---|---|---|
| 問題の結果 | 上に問題画像、下に自分の回答・得点・Mortalの最善手 | その問題 |
| 問題集の結果 | 得点・ピタリ数・各問の得点 | その問題集 |
| 成績 | 回答数・平均点・ピタリ率 | 成績画面 |

- 共有画像は縦3:4の決まった配置でブラウザーが生成する。OSの共有機能で画像と投稿文を渡し、使えない環境では画像を保存させてXの投稿画面（投稿文＋リンク）を開く。
- リンク先の画面は、見た人の回答履歴で表示を変える（未回答なら出題、回答済みなら結果）。
- リンクのOGPカードはサイト共通の画像とする。

## 問題画像

問題データからブラウザーで描く。回答者の席を画面下に置き、次を必ず含める。

- 問題番号、局・本場・供託、残り枚数、ドラ表示牌
- 4人の点数・自風（親を区別）
- 4人の河（リーチ宣言牌は横向き、ツモ切りを区別）と副露
- 自分の手牌（打牌問題はツモ牌を離して置く）
- 鳴き問題は対象の捨て牌を強調し、「チーする？」等の問いを表示する

## 問題生成

- ルールはMortalの対局エンジン（libriichi）に従う（天鳳段位戦準拠の東南戦、赤5各1枚）。4席ともMortalが貪欲選択で打つ。
- 対象はMortalの合法手が2つ以上ある打牌判断（リーチ判断を含む）と鳴き判断。和了・カン・九種九牌を選べる判断は対象外。
- 局（局＋本場）ごとに難易度を等確率で1つ選び、その局の該当判断（4席、打牌と鳴きの合算）から1つを無作為に抽出する。該当がなければその局からは出題しない。
- リーチ判断は抽出の重みを上げ、問題全体の約5%にする（自然な割合は約2.5%）。重みは生成データで調整する。
- 抽出後、問題の並びを固定seedでシャッフルして1から番号を振る（問題集が同じ半荘の連続した局に偏らないようにする）。1万問を公開前にすべて生成・投入する。
- 対局・抽出・並べ替えの乱数を固定し、同じ入力から同じ問題集合を再現できるようにする。
