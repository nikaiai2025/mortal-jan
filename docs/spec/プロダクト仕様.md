# プロダクト仕様

麻雀の何切る問題を画像で出題し、回答をAI（Mortal）の評価で採点するWebサービス。問題はMortal同士の自己対局から事前に生成する。ユーザー登録は不要。

評価モデルは第三者が配布するMortal用の重み（mortal-298k）であり、公式モデルではない。画面の評価は「AI評価」と呼び、サイト名は「〜 powered by Mortal」の形にする。サイトにはモデル名・出典・ライセンスとソースコードへのリンクを表示する。

## 画面

| 画面 | URL | 内容 |
|---|---|---|
| 出題 | `/` | 問題画像と回答ウィンドウ |
| 問題の結果 | `/q/{問題番号}` | 自分の回答と得点、候補ごとのAI評価、人にとっての難しさ |
| 問題集 | `/sets?theme={テーマ}`、`/sets/{テーマ}/{問題集番号}` | テーマ別の一覧（完了状況と得点）、10問の出題、まとめの結果 |
| 成績 | `/u/{公開ID}` | 回答数・平均点・ピタリ率と回答履歴 |
| ランキング | `/ranking` | 期間×評価軸の順位 |
| ルール | `/rules` | 問題の出どころ（全員Mortalの対局）、対局ルール、採点と難易度の説明 |

盤面の下には、天鳳段位戦準拠の東南戦で対戦相手も全員Mortalであることを一行で示し、ルールへリンクする。

## 出題と回答

- 打牌問題は盤面の自分の手牌をタップして選び（リーチできる局面では回答ウィンドウのリーチも押す）、鳴き問題は回答ウィンドウの選択肢（チーの組合せ・ポン・スルー）から選ぶ。回答ウィンドウの「確定」で送信する。
- `/`ではサーバーが未回答の問題から無作為に割り当てる。
- 回答画面に出した問題は回答するまで割り当て中とし、その間は他の問題を回答画面に出さない（再読込・モード切替・URL指定で問題を選り好みさせない）。
- `/q/{問題番号}`を未回答で開いた場合はその問題を出題する。
- 1問につき最初の回答だけを記録する。問題集でも同じ記録を使う。
- 回答の保存は1人1日300問まで（暫定、承認待ち）。D1無料枠の書き込みを1人で使い切られないようにするため。

## 採点

Mortalは候補ごとに行動の価値（Q値`q`、単位はモデル固有）を出す。これを全問題共通の温度`T = 1.0`で変換する。`T`は公開後に変更しない。

- AI評価: `p = softmax(q / T)`。候補の合計が100%になる。
- 得点: `100 × p / p_max`（= `100·exp((q − q_max) / T)`）を整数に丸める。最善手以外は最大99点とする。
- ピタリ: 選んだ手がAIの最善手と一致すること。
- 候補は行動単位とする。同じ牌種の打牌は1候補、赤5と通常の5は別候補。
- リーチできる局面の候補は、ダマの各打牌と「リーチ＋各打牌」。後者のQ値は、リーチのQ値＋（宣言後の局面での打牌のQ値−その最大値）とする。

## 難易度

- 生成時の分類は`p_max`（最善手のAI評価）で行う。0.98以上の自明な判断は出題しない。
- 打牌問題（リーチを含む）は、かんたん: 0.9以上、ふつう: 0.5以上0.9未満、むずかしい: 0.5未満。
- 鳴き判断は`p_max`が高く偏るため、打牌問題と同じ難易度の比率になる分位点を閾値にする（100半荘の試算で、かんたん約0.96以上、むずかしい約0.65未満）。
- 人にとっての難しさは、公開後のプレイヤー統計（その問題の平均点）で示す。回答後の結果画面にだけ参考として出し、回答が10件未満の間は出さない。

## 問題集

- テーマは全問・かんたん・ふつう・むずかしい・打牌・リーチ・鳴き。テーマの問題を番号順に並べ、10問ずつ区切る（端数の問題は問題集にしない）。
- 利用者が条件を組み合わせて作る「アソート問題集」は、有料版の機能として準備中の表示だけを置く。
- 未回答の問題を番号順に出題し、1問ごとに結果を見せる。10問そろったら得点（合計÷10、0～100点、小数1桁）・ピタリ数・各問の得点をまとめて表示する。
- 他の画面で回答済みの問題は、その回答を問題集の得点に使う。

## 回答後の演出

1問を解いた直後の演出を最重要のUXとして扱う。赤ペンで採点されるような体験にする。

- 得点に応じた印を書き順どおりに描き、ペンで書く音を鳴らす。ピタリは花丸、70～99点は○、30～69点は△、0～29点は✕。
- 印に続いて得点を書く。打牌問題では、印と得点を盤面の左上へ寄せ、手牌の各牌の上へ切ったときのAI評価の棒グラフを伸ばす（リーチできる牌はダマとリーチの2本）。鳴き問題は候補ごとの評価を一覧で示す。
- 演出はタップで早送りできる。音はオン・オフを切り替えられる。
- 演出の後は、盤面をタップすると印が薄くなり、局面を見直せる。

## ランキング

- 期間は全期間と今日（日本時間0時区切り）。
- 評価軸は回答数・平均点・ピタリ率。
- 平均点とピタリ率は、全期間50問・今日10問以上回答したプレイヤーだけを載せる。

## プレイヤー

- 初回アクセス時に匿名プレイヤーを発行し、端末に保存する。端末のデータを失った場合、成績は引き継げない。
- ユーザー名は任意（12文字以内、禁止語を拒否）。ランキングと成績画面に表示し、未設定なら「名無し#公開ID」とする。

## SNS共有

| 共有元 | 画像 | リンク先 |
|---|---|---|
| 問題の結果 | 上に問題画像、下に自分の得点と印。答え（自分の回答・AIの最善手）は載せない | その問題 |
| 問題集の結果 | 得点・ピタリ数・各問の得点 | その問題集 |
| 成績 | 回答数・平均点・ピタリ率 | 成績画面 |

- 共有画像は縦3:4の決まった配置でブラウザーが生成する。OSの共有機能で画像と投稿文を渡し、使えない環境では画像を保存させてXの投稿画面（投稿文＋リンク）を開く。
- リンク先の画面は、見た人の回答履歴で表示を変える（未回答なら出題、回答済みなら結果）。
- 問題の結果のリンクには共有した人を付け、リンクから解いた人の結果画面に共有した人の回答と得点を並べる。
- リンクのOGPカードはサイト共通の画像とする。

## 問題画像

問題データからブラウザーで描く。回答者の席を画面下に置き、次を必ず含める。

- 問題番号、局（本場・供託は0でないときだけ）、残り枚数、ドラ表示牌
- 4人の点数・自風（親を区別）
- 4人の河（リーチ宣言牌は横向き、ツモ切りを区別）と副露。リーチした人は点棒・「リーチ」の札・河の下地で目立たせる
- 自分の手牌（打牌問題はツモ牌を離して置く）
- 鳴き問題は対象の捨て牌を強調する

「何を切る？」「チーする？」等の問いは、回答ウィンドウと共有画像に出す。

## 問題生成

- ルールはMortalの対局エンジン（libriichi）に従う（天鳳段位戦準拠の東南戦、赤5各1枚）。4席ともMortalが貪欲選択で打つ。
- 対象はMortalの合法手が2つ以上ある打牌判断（リーチ判断を含む）と鳴き判断。和了・カン・九種九牌を選べる判断は対象外。
- 局（局＋本場）ごとに、鳴き枠か打牌枠かを選び、次に難易度を等確率で1つ選んで、その枠・難易度の判断（4席分）から1つを無作為に抽出する。該当がなければその局からは出題しない。
- 鳴き問題は全体の約20%（暫定）、リーチ判断は約5%になるよう、鳴き枠を選ぶ確率とリーチ判断の抽出の重みを生成データから定める。
- 抽出後、問題の並びを固定seedでシャッフルして1から番号を振る（問題集が同じ半荘の連続した局に偏らないようにする）。1万問を公開前にすべて生成・投入する。
- 対局・抽出・並べ替えの乱数を固定し、同じ入力から同じ問題集合を再現できるようにする。本番の乱数seedはリポジトリに含めない（公開コードから問題と答えを再現されないため）。
