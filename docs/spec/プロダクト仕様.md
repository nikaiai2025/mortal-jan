# プロダクト仕様

麻雀の何切る問題を画像で出題し、回答をAI（Mortal）の評価で採点するWebサービス。問題はMortal同士の自己対局から事前に生成する。ユーザー登録は不要。

評価モデルは第三者が配布するMortal用の重み（mortal-298k）であり、公式モデルではない。画面の評価は「AI評価」と呼ぶ。サイト名は仮に「もーたる何切る教室」とする（Mortalの名称の使用は作者に確認中）。サイトの下部に、制作者のX（@shika_bakudan）へのリンク、AIで開発したこと（使用ツールはブランド名でClaude, ChatGPTと書く）とCloudflareの無料枠でサーバー代が0円であること、採点のモデル名（第三者配布の重みであること）とMortalへのリンク、ソースコードへのリンクとライセンスを表示する。専門用語はライセンス名だけにする（麻雀をする人の多くはITに詳しくない）。

## 画面

| 画面 | URL | 内容 |
|---|---|---|
| 出題 | `/` | 問題画像と回答ウィンドウ。回答後に次の問題の選び方（ランダム／番号順） |
| 問題の結果 | `/q/{問題番号}` | 自分の回答と得点、候補ごとのAI評価、人にとっての難しさ |
| 今日の10問 | `/daily` | 全員共通の10問の出題とまとめの結果 |
| 問題集 | `/sets?theme={テーマ}`、`/sets/{テーマ}/{問題集番号}` | テーマ別の一覧（完了状況と得点）と番号を指定して開く欄、10問の出題、まとめの結果 |
| 成績 | `/u/{公開ID}` | 回答数・平均点・ピタリ率、1日ごとの平均点のグラフ（回答した日だけ）、難易度別・種類別の成績と回答履歴（本人だけ。「間違い」に絞れる） |
| ランキング | `/ranking` | 期間×評価軸の順位 |
| ルール | `/rules` | 対局ルール、遊び方（解き直しはできない）、採点、成績とランキング |

出題・結果の画面には「東南戦（半荘戦）・天鳳準拠　4人ともガチレベルの打ち手」「赤ドラあり（5萬・5筒・5索に各1枚）。喰いタン・後付けあり。一発・裏ドラ・槓ドラあり。」「暗い表示はツモ切り」と書き、詳細ルール（`/rules`）へリンクする。

## 出題と回答

- 打牌問題は盤面の自分の手牌をタップして選び（リーチできる局面では回答ウィンドウのリーチも押す）、鳴き問題は回答ウィンドウの選択肢（チーの組合せ・ポン・スルー）から選ぶ。回答ウィンドウの「確定」で送信する。
- 問いは手牌のすぐ上に置く。打牌・リーチの「確定」は問いの横に、鳴きの選択肢と「確定」は盤面の外に置く（回答の前後で盤面の大きさを変えない）。入力の間に回答と関係のない表示を挟まない。
- 盤面の上には何も置かない（盤面が押し下げられてスクロールが要るため）。盤面の外のものは盤面の下に、鳴きの選択肢・回答後の結果、問題集の進み具合と案内、ルールの注記の順に置き、問題と回答欄の間に他の表示を挟まない。横長の画面（PC）では盤面の右に置き、ルールの注記と問題集の進み具合は盤面の上端に、鳴きの選択肢と結果は盤面の下端にそろえる。スクロールせずに次の問題へ進め、手牌や「確定」からのマウスの移動も短くするため。
- 選べる手牌には光が順に流れ、タップできることを示す（牌を選ぶと止める）。
- `/`は次の問題の選び方（ランダム／番号順）を端末に保存して出題する。ランダム: 未回答から無作為に割り当てる。解きかけの問題（開いたまま未回答）があればそれを先に出す。番号順: 最後に回答した番号の次の未回答を出す（最後まで解いたら最初から）。切替は回答後の「次の問題へ」の横に置き、次の問題から効く。出題中の画面には問題に集中させるため、選び方や番号指定の操作を置かない。難易度・種類で選ぶ入口と番号指定は問題集のページに置く。
- `/q/{問題番号}`を開くと、未回答なら出題し、回答済みなら結果を出す。どの問題もいつでも開ける。解きかけの問題を残して他の問題へ移ることは許容する（厳密さより気軽さを優先する）。
- 1問につき最初の回答だけを記録し、解き直しはできない。問題集・今日の10問でも同じ記録を使う。回答済みの問題はいつでも結果を見直せる。
- 新しく出題するのは1人1日1,000問まで（日本時間0時で戻る）。D1無料枠の書き込みを1人で使い切られないようにするため。回答済みの問題は上限後も見られる。

## 採点

Mortalは候補ごとに行動の価値（Q値`q`、単位はモデル固有）を出す。これを全問題共通の温度`T = 1.0`で変換する。`T`は公開後に変更しない。

- AI評価: `p = softmax(q / T)`。候補の合計が100%になる。
- 得点: `100 × p / p_max`（= `100·exp((q − q_max) / T)`）を整数に丸める。最善手以外は最大99点とする。
- ピタリ: 選んだ手がAIの最善手と一致すること。
- 候補は行動単位とする。同じ牌種の打牌は1候補、赤5と通常の5は別候補。
- リーチできる局面の候補は、ダマの各打牌と「リーチ＋各打牌」。後者のQ値は、リーチのQ値＋（宣言後の局面での打牌のQ値−その最大値）とする。

## 難易度

- 生成時の分類は`p_max`（最善手のAI評価）で行う。0.96以上の自明な判断は出題しない。
- 打牌問題（リーチを含む）は、かんたん: 0.78以上、ふつう: 0.57以上0.78未満、むずかしい: 0.57未満（0.96未満の判断をほぼ3等分する値）。
- 鳴き判断は`p_max`が高く偏るため、打牌問題と同じ難易度の比率になる分位点を閾値にする（値は`generator/calibration.json`）。
- 閾値は公開後も変えられる。変えたら出題済みの問題の難易度を付け直す（難易度別の問題集の中身、過去の回答の花丸の種類、難易度別の成績が変わる）。
- 人にとっての難しさは、公開後のプレイヤー統計（その問題の平均点）で示す。回答後の結果画面にだけ参考として出し、回答が10件未満の間は出さない。

## 問題集

- テーマは全問・かんたん・ふつう・むずかしい・打牌・リーチ・鳴き。テーマの問題を番号順に並べ、10問ずつ区切る（端数の問題は問題集にしない）。
- 未回答の問題を番号順に出題し、1問ごとに結果を見せる。10問そろったら得点（合計÷10、0～100点、小数1桁）・ピタリ数・各問の得点をまとめて表示する。
- 他の画面で回答済みの問題は、その回答を問題集の得点に使う。

## 今日の10問

- 日本時間の日付ごとに、全員共通の10問を番号順に出す。その日に最初に求められたとき、回答数が最も少ない問題から選ぶ（同数なら無作為）。
- 出題とまとめの結果は問題集と同じ。他の画面で回答済みの問題はその回答を使い、上書きしない。
- 10問そろった時点で、その人のその日の結果（得点・ピタリ数・完了時刻）を記録する。完了時刻は10問目を回答した時刻（その日が始まる前にそろっていた場合は、今日の10問を最初に開いた時刻）。日本時間0時をまたいで前日の10問目を回答した場合は、前日の結果として記録する。
- 共有リンクは`/daily`。同じ日のうちだけ同じ問題を指す。

## 見直し

- 成績の回答履歴は「すべて」「間違い（△・✕）」に絞れる。間違いから開いた結果画面には「次の間違いへ」を置き、履歴の順にたどれる。

## 回答後の演出

1問を解いた直後の演出を最重要のUXとして扱う。赤ペンで採点されるような体験にする。

- 得点に応じた印を書き順どおりに描き、ペンで書く音を鳴らす。ピタリは花丸、70～99点は○、30～69点は△、0～29点は✕。
- 花丸はプレイヤーと問題の組ごとに決まる（採点・共有画像・一覧で同じ種類を出す）。むずかしい問題では、うずまきの3種類が各30%、レアA（にこにこ顔）が6%、レアB（顔と茎・葉のある花）が4%。それ以外の難易度ではレアBをレアAに置き換え、うずまきの3種類が各30%、レアAが10%。
- 印はすべて同じ赤ペン（同じ色・太さ）で描く。人が描いたように見せるため、描くたびにペンの進行方向の左右へ少しずつ違うブレを入れる。
- 印に続いて得点を書く。印と得点は盤面の上半分に書き、動かさない。打牌問題では、手牌の各牌の上へ、切ったときのAI評価の棒グラフを伸ばす（リーチできる牌はダマとリーチの2本）。グラフは自分の河と手牌の間に収め、最大まで伸びても盤面に重ねない。グラフを出しても盤面を動かさない（グラフの場所は出題中の回答ウィンドウの場所）。鳴き問題は候補ごとの評価を一覧で示す。
- 演出はタップで早送りできる。音はオン・オフを切り替えられる。
- ヘッダーの「演出」をOFFにすると、印は書かずに一瞬で出し、得点だけを書く（鳴るのは得点を書く音とピタリの音だけ）。音と演出の設定は端末に保存する。
- 演出の後は、盤面をタップすると印が薄くなり、局面を見直せる。

## ランキング

- 期間は全期間と今日（日本時間0時区切り）。
- 全期間の評価軸は回答数・平均点・ピタリ率。平均点とピタリ率は50問以上回答したプレイヤーだけを載せる。各行に難易度別の回答数の帯（かんたん・ふつう・むずかしいの比）を示す。順位には影響させず、解き方の偏りを見えるようにするため。
- 今日は、今日の10問を解き終えた人を得点、ピタリ数、完了時刻の早い順に並べる。
- 各ランキングの1〜3位（同順位を含む）には金・銀・銅の王冠と「You are Mortal」の称号を付ける。

## プレイヤー

- 初回アクセス時に匿名プレイヤーを発行し、端末に保存する。端末のデータを失った場合、成績は引き継げない。
- ユーザー名は任意（12文字以内、禁止語を拒否）。ランキングと成績画面に表示し、未設定なら「名無し#公開ID」とする。

- 投稿文は、共有するもの（「第12問」「問題集 第4集」「今日の10問（10月2日）」「私の成績」）とハッシュタグ「#もーたる何切る教室」、リンクだけにする。

- リンクのOGPカードはサイト共通の画像とする。

## 問題画像

問題データからブラウザーで描く。回答者の席を画面下に置き、次を必ず含める。

- 問題番号、局（枠で囲んだ「東1局」と、その横に供託の千点棒・本場の百点棒の本数）、残り枚数
- ドラは王牌として5枚並べる。ドラ表示牌を左端に表向きで置き、残りは裏向き。カンドラが出るたびに左から1枚ずつ表にする
- 4人の点数・自風（親を区別）。点数は回転させず、全員分を正立で大きく書く
- 4人の河（リーチ宣言牌は横向き、ツモ切りは暗く表示。鳴かれた牌も河に残し、丸で囲んだ「鳴」の印を重ねる）と副露。河は6枚ずつ3段までとし、19枚目以降は3段目を右へ伸ばす。他家の手牌は河のすぐ外に置く。リーチした人は点棒・「リーチ」の札・河の下地で目立たせる
- 自分の手牌（打牌問題はツモ牌を離して置く）
- 鳴き問題は対象の捨て牌を赤丸で囲み、選択肢で使う手牌（赤5は5と同じ扱い）をひとまとまりとして上辺に1本の長い赤線を引いて、赤丸と1本の線でつなぐ

「何を切る？」「鳴く？」等の問いは、画面でも共有画像でも盤面の手牌のすぐ上に1回だけ置く。

## 問題生成

- ルールはMortalの対局エンジン（libriichi）に従う（天鳳段位戦準拠の東南戦、赤5各1枚）。4席ともMortalが貪欲選択で打つ。
- 対象はMortalの合法手が2つ以上ある打牌判断（リーチ判断を含む）と鳴き判断。和了・カン・九種九牌を選べる判断は対象外。
- 局（局＋本場）ごとに、鳴き・リーチ・打牌（リーチを選べない判断）のどの枠かを選び、次に難易度を等確率で1つ選んで、その枠・難易度の判断（4席分）から1つを無作為に抽出する。枠どうしは混ぜない。選んだ枠の判断がその局になければ打牌枠にし、選んだ難易度の判断がなければその局からは出題しない。
- 鳴き問題が全体の15%、リーチ問題が15%、打牌問題が70%になるよう、鳴き枠とリーチ枠を選ぶ確率を生成データから定める。
- 抽出後、問題の並びを固定seedでシャッフルして1から番号を振る（問題集が同じ半荘の連続した局に偏らないようにする）。公開前に1万問を投入する。
- 公開後に問題を増やすときは、投入済みの問題と番号を変えず、まだ問題を出していない局から抽出した追加分だけをシャッフルして続きの番号を振る。投入済みの問題は消さない。
- 対局・抽出・並べ替えの乱数を固定し、同じ入力から同じ問題集合を再現できるようにする。本番の乱数seedはリポジトリに含めない（公開コードから問題と答えを再現されないため）。
