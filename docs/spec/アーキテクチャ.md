# アーキテクチャ

## 構成

| 部分 | 技術 | 役割 |
|---|---|---|
| 問題生成 | Python（Mortal・libriichi） | 自己対局から問題データを作る。公開前に一度だけ実行する（公開後は難易度の付け直しだけ） |
| Web API | Cloudflare Workers、D1 | 出題・採点・ランキング（`web/worker`） |
| Webクライアント | TypeScript（フレームワークなし）、Vite | 画面・演出・共有画像（`web/client`）。問題画像と共有画像はCanvas、印はSVG、音はWeb Audioの合成で作り、画像・音声ファイルを配信しない |

- WebはMortalを実行しない。採点に使うQ値は問題データとしてD1に持つ。
- APIはWorkers無料プランのCPU上限（1リクエスト10ms）に収める。サーバーで画像を生成しない。
- 配信はGitHub Actionsの手動ワークフロー（Deploy）で行い、D1のマイグレーションを当ててからWorkerを配信する。問題データの投入は公開前に一度だけ行う。

## 問題生成パイプライン

| 段 | 処理 | 出力 |
|---|---|---|
| selfplay | libriichiの対局エンジンで自己対局する | mjaiログ（`.json.gz`） |
| evaluate | ログを席ごとにlibriichiの`PlayerState`で再生し、行動可能な全時点の特徴量をまとめて推論する | 判断点ごとのQ値 |
| calibrate | 鳴きの難易度の閾値、鳴き枠とリーチ枠を選ぶ確率を判断データから導出する | `generator/calibration.json` |
| extract | [プロダクト仕様](プロダクト仕様.md)の対象・難易度・抽出・番号付けの規則を適用する | 問題JSONL |
| export_logs | 問題の生成元ログから1局ぶんを天鳳JSONに変換する | 問題別の牌譜JSON・D1投入SQL |
| load | D1投入SQLを作る | — |
| relabel | 閾値を変えたとき、投入済みの問題の難易度と難易度内の通し番号を付け直し、集計表の難易度別の回答数を数え直すSQLを作る | — |

- libriichiのアリーナは同じseedを4回転（席替え）で打つため、同一モデル同士では4局とも同じ対局になる。1seedにつき1対局だけを生成する。
- アリーナのログには実行された行動のQ値しか残らず、見送った鳴きが欠ける。Q値はevaluateで取り直し、ログに残るQ値（リーチ宣言後を含む）と一致することを照合する。
- リーチを選べる判断は、その局面にリーチ宣言を加えた状態も推論し、リーチ打牌の候補を作る。
- 生成物にはMortalのソースcommitと重みのSHA-256を記録する。

## データ（D1）

| テーブル | 主な列 |
|---|---|
| problems | 番号、種別、難易度、局面データ、評価データ（候補とQ値・最善手）、生成元（seed・局・本場・席・イベント位置）、難易度内・種類内の通し番号（テーマ別問題集用）、回答数、得点合計 |
| problem_logs | 問題番号、事前変換した1局ぶんの天鳳JSON。表示時だけ読み、通常の出題・採点には含めない |
| players | 内部ID、公開ID、トークンのハッシュ、名前、最後に開いた問題（回答はこの問題だけ受け付ける）、その日の割り当て数（1日の上限に使う） |
| answers | 連番、プレイヤー、問題、選んだ行動、得点、ピタリ、回答日時、日本時間の日付（プレイヤー×問題で一意） |
| player_stats | プレイヤー、期間（全期間または日本時間の日付）、回答数、得点合計、ピタリ数、ランキング対象か、平均点、ピタリ率、難易度別の回答数（全期間の行だけ。ランキングの帯） |
| aggregation | 集計済みの回答の連番 |
| daily_sets | 日本時間の日付、その日の10問の番号 |
| daily_results | 日付、プレイヤー、得点合計、ピタリ数、完了時刻（今日のランキングの索引） |

- 局面データは回答者の席から見える情報だけを持ち、回答前に返してよい。評価データは回答後にだけ返す。
- 記録する事実は回答（`answers`）だけで、回答時の書き込みは回答1行・一意の索引1行・次の割当1行の計3行。1日の上限は割当の行で数えるので、書き込みも読み取りも増えない。
- ランキング用の`player_stats`と問題の回答数・得点合計は、10分ごとの定期実行（Cron Trigger）が前回以降の回答を足し込む（`worker/aggregate.ts`）。ランキングと人にとっての難しさは最大10分遅れる。
- 自分の成績・回答履歴・問題集の進み具合は、本人が表示するたびにその人の回答から数える。難易度別・種類別の成績は回答と問題を突き合わせて数え、難易度を回答に書き写さない（閾値を変えても問題を付け直すだけで済ませるため）。例外は全期間ランキングの難易度別の回答数で、集計時に問題の難易度を読んで足し込み、閾値を変えたときはrelabelのSQLが数え直す。他人の成績ページ（共有リンク）は集計済みの値だけを返し、履歴は出さない。全回答を走査する集計はしない（D1は読んだ行数で制限されるため）。
- ランキングは`player_stats`と`daily_results`の索引から上位を読み、短時間キャッシュする。D1は読んだ行数で課金・制限されるため、`answers`の全件走査で集計しない。
- 今日の10問は、その日に最初に求められたときに問題テーブルを1回走査して選び、`daily_sets`に保存する。完了は回答時に判定し（その問題が今日の10問に入るときだけ10行読む）、`daily_results`に1行書く。
- 番号順の出題は、指定番号より大きい問題を番号順に歩いて回答の索引を引き、最初の未回答で止まる（読む行数は数行）。

## プレイヤー識別

- プレイヤー発行時にランダムなトークンを返し、D1にはハッシュだけを保存する。APIはトークンで本人を識別する。
- 書き込みAPIにレート制限を掛ける。
