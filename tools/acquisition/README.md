# 集客と利用の計測

検索の表示・クリックはSearch Console、ページの訪問・速度はCloudflare Web Analyticsで見る。このツールは、最初の訪問元から回答・再利用へのつながりを集計する。Cloudflareの訪問回数を、この集計の人数の分母には使わない。

## 指標

| 指標 | 定義 |
|---|---|
| 新規訪問者 | 計測開始後に初めて識別されたブラウザ。過去に回答済みのプレイヤーと、既に別のブラウザで計測された同じプレイヤーは除く |
| 初回回答者 | 最初の回答が保存されたプレイヤー。初回回答の日付で数え、HTTPの再送信を数えない |
| 24時間以内の初回回答率 | 初回訪問から24時間以内に回答した人数 ÷ 新規訪問者数。初回訪問の日付ごとに観測が終わった集団だけを含む |
| 7日以内の再利用率 | 初回回答の翌日から7日目までに新しい回答を保存した人数 ÷ 初回回答者数。初回回答の日付ごとに観測が終わった集団だけを含む |

日付は日本時間。日付単位で全員の観測が終わるまで待つため、回答率では集計日の2日前まで、再利用率では8日前までを使う。まだ観測対象がない割合は「観測待ち」と表示する。

流入元はブラウザの最初の訪問に固定する。投稿のUTMを優先し、ない場合は参照元から分類する。`unknown`は直接訪問または判別不能で、検索語と個別の回答者を結び付けるものではない。端末変更・保存データ削除による重複、計測拒否・通信失敗・自動アクセスによる欠測や混入は残る。数字は実人数の厳密な証明には使わない。

## 投稿リンク

```powershell
node tools/acquisition/link.mjs --url https://mortal-jan.shika.workers.dev/daily --source x --campaign first-trial --content post-01
```

試行名と投稿名は英小文字・数字・ハイフン・アンダースコアの48字以内にする。同じ投稿には同じ投稿名を使い、別の投稿には別名を付ける。生成したURLを投稿に使う。リンクに印を付けるだけでは計測できず、マイグレーション0006と今回のWeb実装の本番反映が必要。

## 集計

```powershell
node tools/acquisition/report.mjs --remote --from 2026-10-05 --to 2026-10-18 --output trash/acquisition/report.md
```

本番は`--remote`、ローカル検証は`--local`を明示する。現在のCloudflare認証を使った読み取り専用の操作で、Webへ集計APIを公開しない。期間は1〜90日。日別の集計テーブルと索引を読み、回答の全件走査はしない。まず初回回答者数を見て、割合は分子・分母の人数と一緒に比較する。少数の回答だけで投稿の優劣を断定しない。

## 計測の管理

自分の動作確認は`https://mortal-jan.shika.workers.dev/?measure=off`を開いて除外する。再開は`?measure=on`。収集APIの本番検証には予約済みの試行名`internal-check`を使い、集客の人数には含めない。一般の利用者は「このサイトについて」から訪問元と回答の計測を停止できる。この設定は端末ごとで、ゲームの回答記録と既存のCloudflare Web Analyticsは変更しない。

収集するのは匿名IDのハッシュ、プレイヤーとの対応、分類済みの流入元・入口、試行・投稿の識別子、初回訪問と回答・再利用の時期。氏名・IPアドレス・認証トークン・復活の呪文・参照元の生URL・任意のクエリは収集しない。独立したレート制限を設け、計測の保存失敗は回答の保存を取り消さない。既存の回答へ索引が1つ増えるため、書き込みと保存容量の使用量は増える。
